# E1 规则型：《崂山道士》C 档改编

**素材**：蒲松龄《聊斋志异·崂山道士》（公有领域）。

**要点**：王七求道，受不了砍柴之苦，求师父教穿墙术。师父授口诀，嘱“归宜洁持，否则不验”。王七回家向妻子炫耀，穿墙时头撞硬壁，额起大包。

## 给模型的请求

```text
把《聊斋志异》里的《崂山道士》改编成剧本。换掉人名、地名和具体设定，重做冲突。直接写剧本。
```

## 硬检查点

1. 原文的三层条件——**口诀**、**持守（心念不纯则不灵）**、**入时不能迟疑**——在新稿里都有对应，且不能只在首次成功时出现。
2. **私念或炫耀导致失效**这一语义保留，失效表现为规则结算，不是偶发意外。
3. 师父授术有**明确附带条件**，主角当场知晓；条件不是事后追加的解释。
4. 主角的成功与失败都因同一套规则；失败不是被敌人或外力造成。
5. C 档去标签后，对照 [mechanism-contract.md](../../references/mechanism-contract.md) 的四个维度（决定节点、关系网、信息揭示、解决方式与结尾），每一维都不能逐项对回原作（类型共有的节拍除外）；任一维仍能逐项对回即判失败。
6. 用同名或谐音（如“王七”“崂山”）命名主角，硬失败。
7. 正文中出现能力升级、能力扩用或临时例外，硬失败。

## 观察项

- 是否在正文中自然交代规则，而不是集中说明。
- 失败之后的余波是否有正文依据（不只是羞惭一句台词）。
- 是否选用了 [medium-profiles.md](../../references/medium-profiles.md) 之外的节奏参数（不必，但记录）。

## 常见失败

- 把“不能炫耀”改成“被反派搅乱”，规则失效机制被替换。
- 保留砍柴细节和原文场景顺序，只换名字。
- 结尾用原文“额上坟起如巨卵”的意象换个说法就算兑现。
