# E6 返修与依赖更新

**素材**：先由评测者按 E1 跑一次 C 档改编，保存为“已采用版本”，再发下面的返修请求。

## 给模型的请求

```text
上一版我用了（附上一版正文）。现在把师父这个角色改成主角的姐姐，另外主角最后不该撞墙，改成他自己走进墙里消失了。其他保留，给我完整替换场次。
```

## 硬检查点

1. 先读取已提供版本，确认**改变项**（角色关系、结尾结果）与**保留项**，不擅自重做其他部分。
2. 替换场次**标明原场次编号、替换范围和前后衔接**，可直接替换进原稿；不是给修改建议。
3. 改动后的依赖被一并更新，至少覆盖：
   - 该角色的称呼与引用（人物表、对白称呼、他人指代）；
   - 事件因果（授术动机与条件是否仍成立）；
   - 后续场次中对原结尾的描述或铺垫。
4. 结尾从“穿墙失败”改为“消失”时，**原失败所兑现的代价与教训**没有被无声取消；新结尾的代价或后果有正文依据，或在交付说明中指出这一变化并确认是否需要补。
5. 不因为改了结尾就顺手改动机制语义，除非用户要求。

## 观察项

- 是否更新承接记录（若上一版有）。
- 是否把无关场次重写（不必，记录即可）。

## 常见失败

- 只交改后的两场，不标原场次，无法衔接。
- 改了角色关系，但前文对白里仍用“师父”的旧称呼。
- 结尾改成消失后，前面的“心念不纯”一线失去落点却没有处理。
