# novel-to-visual-script（小说保核改编剧本）

把小说、章节或梗概改编成可观看、可聆听的中文剧本的 Agent Skill。默认走**保核重构**：保留读者追这个故事的原因、让选择和代价成立的机制，重做人物、关系网、冲突、事件链与结尾。

## 做什么，不做什么

- 做：从原文提取核心与机制、换掉辨识性设定、重建冲突、写完整场次的剧本、按需分批与返修。
- 不做：默认不附分镜、镜头表和 AI 视频提示词；不做质量打分、固定审稿轮数；不把每部作品套进固定短剧节奏。

## 改编档位

按用户措辞自动判档，未指定时按 C 档并在交付说明里注明。

| 档位 | 保留 | 可重做 |
| --- | --- | --- |
| A 忠实改编 | 人物、关系、主要事件、结局、原名称 | 表达、场序、媒介转译、最小缺陷修复 |
| B 换名换景 | 事件链与结局走向 | 名称、物件载体、地点、时代外观、对白 |
| C 保核重构（默认） | 锁定项、核心、必保机制、回报性质 | 实现层全部，含关系网、冲突、事件链、结尾 |
| D 母题再创作 | 锁定项、核心类型、情感作用 | 机制也可重设 |

判档细则与各层定义见 [SKILL.md](SKILL.md) 与 [references/mechanism-contract.md](references/mechanism-contract.md)。

## 文件结构

```text
SKILL.md                        技能入口：档位、硬约束、流程、参考文件索引
agents/openai.yaml              部分宿主的界面元数据（显示名与默认提示词）
references/
  mechanism-contract.md         保留项分层、核心类型表、机制核对、命名、去标签比较
  visual-scene-craft.md         从叙述到场面：人物、信息差与知识表、压缩、动作、审读与模型常见失败
  dialogue-craft.md             对白、潜台词、权力交锋、声音区分、台词禁区、情绪外化与改前改后
  script-format.md              交付格式、分集、返修、下游交接
  worked-example.md             《画皮》C 档示例、《红玉》竖屏短剧示例与七个反例
  medium-profiles.md            电影、剧集、竖屏短剧、广播剧的弹性要求，爽点与集尾原则
  adaptation-state.md           承接记录模板（分批、长篇、跨会话）

evals/                          回归评测：10 个用例、13 个子用例；runs/ 存放历次运行记录
```

运行时只读 `SKILL.md` 与它按需指向的 `references/`；`evals/` 仅用于维护本技能。

## 使用

把整个目录放进宿主的技能目录，目录名与 `SKILL.md` frontmatter 的 `name` 一致（`novel-to-visual-script`），例如用户级 `~/.zcode/skills/novel-to-visual-script/`。

可用的说法：

- 「把这篇小说改成剧本」→ C 档
- 「尽量忠实原著，人名情节都别改」→ A 档
- 「换个背景，人名换掉」→ B 档
- 「只借这个设定写个新故事」→ D 档
- 「改成竖屏短剧，先给前 3 集」→ C 档 + 载体档案 + 分集格式
- 「先给前几场，剩下的下次给你」→ 分批 + 承接记录

默认交付标题、必要的人物表和完整场次；确有需要时交付说明只写档位、范围、取舍与修复项和待确认项。

## 权属前提

默认素材是用户本人作品、公版作品或已获改编授权的作品。素材是他人仍在版权期内的未授权作品、又被要求「改到查不出来」时，技能会简短说明换名换景的风险，改用保核重构或建议取得授权，不提供规避式改法。这不是法律意见。

## 维护

改动 `SKILL.md` 或 `references/` 后，按 [evals/README.md](evals/README.md) 用同一批用例重跑并对比基线，结果记入 `evals/runs/`。放宽检查点要在提交说明里写明理由。
